# 出典ページの見張り

共通ルールは、独自の定義を持たずに外部の定義に沿う。そのため、出典のページが変わったら共通ルールも追いかける。

| ファイル | 中身 |
|---|---|
| `sources.json` | 見張るページ。`start`〜`end` は本文の範囲を示す要素の `id`（ナビゲーションや更新日で騒がないように、使っている節だけを比べる） |
| `snapshots/<id>.txt` | 共通ルールが今もとにしている本文の写し |
| `watch.py` | ページを取得して本文を取り出し、写しと比べる（標準ライブラリだけ） |
| `../.github/workflows/watch-sources.yml` | 毎週月曜に `watch.py --check` を流し、変わっていたら Issue（ラベル `source-changed`）に差分を書く。開いている Issue があればそれを更新する |

## 変わったとき

1. Issue の差分を読み、共通ルール（`used_by` に書いた所）に影響があるかを決める。Claude のスレッドに Issue のリンクを渡して頼んでよい。
2. 取り込む PR で、ルールを直し、`python3 sources/watch.py` で写しを更新して一緒にコミットする（影響がなくても写しの更新だけの PR にする）。
3. PR 本文に `Closes #<Issue 番号>` と書く。

「取り出しに失敗しました」と出たら、ページの構成が変わって `start`・`end` の `id` が無くなっている。ページを開いて新しい `id` を `sources.json` に書く。

## ページを足すとき

`sources.json` に1件足し、`python3 sources/watch.py` で最初の写しを作ってコミットする。
`start`・`end` は、ブラウザの開発者ツールで本文の見出しの `id` を見て決める。
